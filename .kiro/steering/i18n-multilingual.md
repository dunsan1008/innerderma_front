# 다국어(i18n) 지원 규칙

## ⛔ 현재 작업 방침 (2026-08 기준, 최우선)
**번역 관련 작업은 하지 않는다.** 퍼블리싱이 전부 끝난 뒤 마지막에 몰아서 진행한다.
- 새 화면·기능은 **한국어 하드코딩**으로 작업한다. `useT()` / 사전 등록을 하지 않는다.
- 사용자가 프롬프트로 번역을 명시적으로 요청할 때만 아래 규칙을 적용한다.
- 이미 번역이 적용된 기존 컴포넌트는 그대로 둔다(되돌리지 않는다).

아래 내용은 나중에 번역 작업을 재개할 때 쓰는 참고 자료다.

---


## 대상 언어
이 프로젝트는 4개 언어를 지원합니다:
- **한국어** (ko) — 기본 언어
- **中文** (zh) — 중국어 간체
- **日本語** (ja) — 일본어
- **English** (en) — 영어

## 구현 방식
- 외부 라이브러리 없이 자체 i18n (`src/i18n/index.js`)
- 번역 사전: `src/i18n/ko.js`, `src/i18n/en.js`, `src/i18n/zh.js`, `src/i18n/ja.js`
- 훅: `useT()` — 컴포넌트 안에서 현재 언어의 사전 객체를 반환
- 언어 상태: `useUiStore` 의 `lang` — **localStorage(`innerderma.ui`)에 저장**한다
  - 외국인 대상 서비스라 새로고침·재접속마다 언어를 다시 고르게 하면 안 된다
  - 저장값이 없으면 `navigator.languages` 에서 추론하고, 지원하지 않는 언어면 한국어로 폴백
  - 모달 열림 상태는 저장하지 않는다(재접속 시 모달이 떠 있으면 안 되므로 `partialize` 로 `lang` 만 남긴다)
- 언어 변경: 우측 상단 지구본 아이콘 → LanguageModal → 선택 시 즉시 전환

## 새 기능/화면 추가 시 규칙
1. UI에 표시되는 **모든 텍스트**는 사전 파일에 키로 등록하고 `t.xxx.yyy` 로 참조한다
2. 하드코딩된 한국어 문자열을 직접 JSX에 쓰지 않는다
3. 새 텍스트를 추가할 때 **4개 언어 모두** 번역을 함께 넣는다
4. 번역 때문에 텍스트 길이가 달라질 수 있으므로:
   - 고정 폭 레이아웃은 피하고 `min-w` / `flex` / `truncate` 를 활용한다
   - 긴 영어 단어는 `break-words` 또는 `[word-break:break-word]` 로 줄바꿈 처리한다
5. 날짜 형식은 `calendar.yearMonth(y, m)` 함수로 언어별로 다르게 표시한다

## 파일 구조
```
src/i18n/
├── index.js   # useT(), getT(), dictionaries export
├── ko.js      # 한국어 (기본)
├── en.js      # English
├── zh.js      # 中文
└── ja.js      # 日本語
```

## 번역 품질 참고
- 스킨케어/뷰티 분야 전문 용어는 각 언어권에서 실제 사용하는 표현을 따른다
- 브랜드명(InnerDerma, WIM, WHS)과 성분명(SPF, UV)은 번역하지 않고 그대로 둔다
- 제품명(피쓰 코어 리빌드 크림 등)은 현재 더미 데이터이므로 번역하지 않는다 (백엔드 연동 시 서버가 언어별 제품명을 내려줄 예정)
